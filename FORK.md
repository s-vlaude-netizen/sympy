# About this fork

This repository is a **fork of the SymPy computer algebra system**, maintained
independently and developed with the assistance of AI coding tools.

It is **not affiliated with, endorsed by, or supported by the SymPy project or
the SymPy Development Team.** Please do not report problems with this fork to
upstream SymPy: their issue tracker covers their code, not these changes. Bugs
found here belong here.

## Why this fork exists

Upstream SymPy has a policy on AI-generated contributions
([`doc/src/contributing/ai-generated-code-policy.rst`](doc/src/contributing/ai-generated-code-policy.rst))
under which patches that are substantially AI-generated are declined. The
changes collected here are substantially AI-generated, and were declined
upstream on that basis. Rather than discard them, they are published here for
anyone who wants them.

That is a statement of fact about a difference in project policy, not a
complaint about it. Upstream is entitled to set the terms on which it accepts
code, and a fork is the mechanism the licence provides for going a different
way. Anyone who prefers upstream's approach should use upstream SymPy, which
remains the reference implementation.

## AI disclosure

All changes in this fork relative to upstream SymPy were generated by an AI
coding agent, including the code, the tests, the commit messages, and this
file. A human directed the work, chose which findings to pursue, and reviewed
the results, but did not hand-write the patches.

What that means for you, concretely:

- **Every change is accompanied by a regression test** that was verified to
  fail before the change and pass after it.
- **Every change was validated against the existing test suite** for the
  affected subpackages, and several were additionally cross-checked against
  `mpmath` at high precision or against an unmodified upstream checkout.
- **Nothing here has had upstream review.** Upstream review catches things
  that tests and cross-checks do not: unwanted interactions with code the
  author never looked at, API and naming decisions that will not age well,
  and mathematical conventions that are deliberate rather than accidental.
  Where a change touches a branch cut or a domain convention, it reflects one
  defensible reading, and a SymPy developer might reasonably choose another.

Treat this fork accordingly: it is useful if one of the fixed bugs is blocking
you, and it is not a drop-in replacement carrying the same assurances as an
upstream release.

## Relationship to upstream

The fork tracks upstream `master` and holds a set of bug fixes on top. See
[`CHANGELOG-FORK.md`](CHANGELOG-FORK.md) for what those are, each with the
behaviour before and after.

The package is still importable as `sympy`, so installing this fork shadows an
installed upstream SymPy in the same environment. Use a separate virtual
environment if you need both.

## Contributing

Contributions to this fork are welcome, AI-assisted or not, with one condition:
say which it was. Disclosure is not a hurdle here, it is just information a
reviewer needs.

If you have a fix that is primarily your own work, consider sending it to
upstream SymPy first. It will reach far more users there, and this fork would
rather shrink than grow.
